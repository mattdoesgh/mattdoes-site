# CONTEXT

## Vault
The Obsidian source tree of `.md` notes (plus `attachments/`) that the site is built from. Nested vaults (subdirs with their own `.obsidian/`) are skipped.

## Note record
What the vault reader hands Intake: `{ rel, content, mtime }`. `rel` is the vault-relative path used in every error message; `mtime` exists only as the `date:` frontmatter fallback.
Names the fs/pure seam: everything after the Note record is deterministic.

## Intake
The pure module that turns Note records into the Content model. Owns all loud-failure validation (publish kinds, slug rules, date/tags/aliases shapes, duplicate routes, duplicate about), thought splitting, stable thought IDs, sorting, and the slug index.
Invariant: same records in, same model out — no clock, no fs, no env. Error mode: throws with messages that name the offending `rel`.
CT wall-clock math (frontmatter re-anchoring, thought timestamps/ids) comes from `lib/time.js`, the Node-side owner of the CT primitives. `templates/_helpers.js` ships to the browser via the importmap so it can't import `lib/`; it keeps a private duplicate of `tzParts` for display formatting, pinned by `test/time.test.js`.

## Content model
Intake's output: articles + thoughts + about note + slug index, all carrying raw markdown (never HTML). Articles and thoughts are newest-first; thought IDs are assigned oldest-first from CT wall-clock timestamps.

## Section descriptor
The static table in `lib/sections.js`: one entry per timeline section (journal, making, thoughts, listening) carrying its route, whether it's a valid `publish:` kind, whether notes get per-note article pages, and its empty-state copy. Consumed by Intake (`routeFor`, `PUBLISH_KINDS`), the sitemap's static routes (`lib/emit/feeds.js`), and Emit's per-section listing loop. Two consumers keep inline copies for their own runtime reasons — `templates/rows.js` (browser-shipped, imports only `_helpers.js`) and the design-system SSG (separate package build) — pinned against the descriptor by `test/sections.test.js`, which also asserts sitemap `<loc>`s exactly match the written index.html pages.

## Emit
The `lib/emit/` directory writes the Content model to a `distDir`: markdown rendering, page rendering, assets, CSP, feeds, search, and Listening entry mapping sit behind the single `emit()` entry (ADR 0009). The pure `lib/notebook.js`, `lib/topic-index.js`, and `lib/editorial-home.js` projections deepen the reader-facing model before the React design system renders it. Emit is deterministic given its inputs; Listening is passed in by the entrypoint. Digs, other recommendations, and the Letterboxd watch snapshot are the same kind of input (`lib/digs.js`, `lib/recommendations.js`, `lib/watches.js`). `/listening/` rows remain the byte-equal `templates/rows.js` exception (ADR 0001).

## Listening
The Last.fm-derived track data (recent scrobbles + playcount). The build-time snapshot (`lib/listening.js`) sources it from the deployed listening Worker's own `/api/listening/recent` route — the production Cloudflare Pages build has no Last.fm credentials, so the Worker (already serving live scrobbles from KV) is the only build-time source that reflects reality. Resolution order: fresh disk cache → Worker → Last.fm direct (only with creds) → stale cache → empty; `LISTENING_OFFLINE=1` skips the network steps for CI/test builds (ADR 0006). It is an input to Emit, not part of the Content model.
The total scrobble count is the recent-tracks `@attr.total` everywhere — the single source the live Worker also uses, so the static stat and the live-updated stat can't disagree. Both consumers decode through `lib/lastfm.js` — the pure wire-format codec (URL builders + decoders, no fetch/fs/config). It is bundled into the listening Worker, so the ADR 0002 redeploy rule applies to it. The Worker itself is a producer/reader split: the Listening poller keeps KV fresh, and the request path is a pure KV reader (ADR 0008), so the build-time `/api/listening/recent` source and its payload shape are unchanged.

## Digs
Weekly music picks authored in the site repo (`content/digs/YYYY-MM-DD.json`), not in the vault. `lib/digs.js` loads and validates them. A pick can be marked `favorite`. Embeds are an allowlist — Apple Music and Bandcamp only — and those two hosts are the `frame-src` exception in `static/_headers`. How to add a week: `docs/recommendations.md`.

## Watches
Recent Letterboxd diary entries for `/movies/`. `lib/letterboxd.js` is the pure RSS codec. `lib/watches.js` fetches the public feed at build time (disk-cached under `.cache/`, skipped when `LETTERBOXD_OFFLINE=1`) and passes the list into Emit. The page keeps the 25 most recent film entries — a recent window, not a full diary, and not a live Worker. Movie watches are not recommendations.

## Recommendations
The `/grok/` page ("grok says…"). Favorite digs are a view over the Digs weeks (`favoritePicks` in `lib/digs.js`) — the hub does not keep a second copy. Anything that is not a dig lives in `content/recommendations.json` (`lib/recommendations.js`). Watches stay on `/movies/`.

## Listening poller
The single Last.fm writer inside the listening Worker — a Durable Object (`ListeningPoller`, singleton via `idFromName('singleton')`) that owns *when* the upstream is called. A self-rescheduling alarm (~25s) makes one `user.getrecenttracks` call, derives both the `/now` and `/recent` payloads from one decode, and writes both KV keys; on failure it writes nothing so the last good snapshot survives. Because it is the only caller, Last.fm volume is constant and independent of visitor traffic, and the request path (the pure KV reader) never blocks on or even knows about Last.fm. A cron watchdog (`[triggers]` in `wrangler.toml`) only arms the alarm if none is pending — liveness, never an upstream call. See ADR 0008.

## Thought
A short public note split out of a daily note on `## HH:MM` headings (CT wall-clock). Carries a stable id `t-YYYYMMDD-HHMM` plus `sourceRel` and `sourceDate`, which preserve daily-note provenance after Intake splits it. A Thought remains independently linkable, but its primary reading context is its Notebook day.

## Notebook day
The reader-facing projection of all Thoughts from one source daily note, keyed by the CT `sourceDate`. `lib/notebook.js` owns the pure grouping rule and preserves Intake's newest-first day and Thought ordering. `/thoughts/` and the homepage render Notebook days; the Vault authoring format stays unchanged.

## Topic path
A durable cross-kind route through the Content model derived from a normalized tag. `lib/topic-index.js` owns normalization, collision-resistant `/topics/<slug>/` paths, cross-kind counts, excerpts, recency, and related-writing ranking. Topic paths connect journal articles, making notes, and Thoughts; query-string filters remain controls for the exhaustive `/blog/` archive.

## Editorial home projection
The pure selection made by `lib/editorial-home.js`: one featured long-form article, two more pieces, recent Notebook days, and developed Topic paths. Emit passes the finished projection to IndexPage. The homepage presents a reading hierarchy; `/blog/` remains the exhaustive reverse-chronological Row timeline.

## Row
The rendered form of one timeline entry — one renderer per content kind (article, thought, listening) plus a per-kind empty state. `/blog/` and the article-kind listings remain timeline surfaces; Notebook days reuse ThoughtRow internally, and the homepage reuses ArticleRow for its subordinate writing section. The in-browser listening live updates retain their byte-equal Row adapter.

The `.row` DOM contract (`.row`/`.gutter`/`.body` markup, `data-kind`/`data-tags`/`data-featured` attributes) has **three consumers**: `templates/rows.js` (the browser Row module, sole owner of the listening-row bytes), the design-system mirrors `TimelineRow`/`ArticleRow`/`ThoughtRow`, and the timeline-controls filter island (`design-system/client/timeline-controls-impl.tsx`). The filter island is emitted only on archive timelines, not the editorial homepage, Notebook, or Topic paths. The dual authority — React mirrors alongside `rows.js` — remains deliberate; see ADR 0010.

## Edge transport
The shared Worker response machinery in `workers/lib/transport.js`: the JSON+CORS envelope, preflight, error cache policy (`errorJson`), fail-open KV access, and request helpers. Caching *policy* (TTLs, cache-control strings) stays per-Worker; only the envelope is shared. `workers/lib/simplify.js` sits alongside it: the pure RDP polygon simplifier shared by the geo Worker and `scripts/bake-home-geojson.js`. Editing either means redeploying all Workers (`npm run deploy:workers`) — see ADR 0002.

## Design system
Current shape (this paragraph supersedes older homepage details below): the page modules now include `ThoughtsPage` and `TopicPage`; `NotebookDay` is a shared reading module; `IndexPage` consumes the Editorial home projection instead of a generic feed. Hero owns the wordmark, tagline, and editorial actions, with no activity-count strip. `/listening/` is the sole `#scrobble-count` emitter through IdentityRail, and `static/listening-live.js` re-stamps it through the shared `formatScrobbleCount`.

The React + TypeScript component library in `design-system/` (`@mattdoes/ds`). One source of truth playing two roles: it renders **every public page** to static HTML at build time (`renderToStaticMarkup`) and it is the component set synced to Claude Design (claude.ai/design) for visual editing. The page components live in `design-system/ssg/pages/` (IndexPage, ArticlePage, BlogPage, ListingPage, AboutPage, ColophonPage), composed from shared chrome components in `src/components/` — `PageShell` (topbar/footer + the status-pill logic, including the manual `siteConfig.status` override), `IdentityRail` (the left "page meta" card), `ElsewhereLinks` (off-site links), and `Hero` (the homepage's full-width intro band — wordmark, tagline, stat strip, action links; it took over the identity/stats duties `IdentityRail` used to carry on the homepage, and its `#scrobble-count` span is the live listening script's target *there* — `/listening/` still renders its own from `IdentityRail`, so the stat markup contract has two emitters — both, along with the live script's re-stamp, format the count through the one shared `formatScrobbleCount` in `templates/_helpers.js`, pinned by `test/scrobble-count-parity.test.js`). The hero's entrance rise and the site-wide hover polish (the "chrome motion" block) are pure CSS in `static/_shared.css`, guarded by `prefers-reduced-motion` — no client JS, no CSP change. The entrance is deliberately hero-only: a page-wide rise would hold content at opacity 0 through the cross-document view-transition crossfade and finish offscreen under speculation-rules prerender (ADR 0007's territory), so page-to-page motion stays owned by the view transition. The document shell — `<head>`, importmap, preloads, enhancement scripts (the old `templates/base.js`) — is `design-system/ssg/document.tsx` (`renderDocument`); and `design-system/ssg/index.tsx` exposes the `render*` functions Emit imports from the built bundle (`dist-ssg/ssg.js`, react external, resolved from `design-system/node_modules`). The head also carries two navigation/UX boot pieces: a synchronous `theme-boot.js` (applies the visitor's saved theme/accent before the stylesheet paints, so a navigation never flashes the default) and a static `<script type="speculationrules">` that prerenders/prefetches same-origin links on intent — allowed by the `'inline-speculation-rules'` CSP source; `static/nav-prefetch.js` is now just the `rel=prefetch` fallback for browsers without the API. Because a hash source in `script-src` disables that directive's keyword inline allowances (`'inline-speculation-rules'` included), the build hashes *every* inline `<head>` script together: `lib/emit/csp.js` (`injectInlineScriptCsp`) appends the `sha256` of the emitted importmap **and** the speculation rules to `script-src` in the dist `_headers`. Drop either hash and the strict CSP silently blocks that script — a dead importmap kills every module that imports through it, dead speculation rules kill prerender/prefetch (ADR 0001, ADR 0007). Because a prerendered document executes its scripts against a stale prefs snapshot, `static/tweaks.js` re-applies on `prerenderingchange`/`pageshow` — see ADR 0007. The two live-update scripts (`static/now-playing.js`, `static/listening-live.js`) share one polling lifecycle: `static/poller.js` (`createPoller`), imported through the importmap like the Row module, owns the visible-tab-only interval, the bfcache-restore resume, and the same prerender deferral — consumers supply only their tick. The migration cutover itself changed nothing visually — components came out of it emitting the old templates' class names against an unchanged `static/_shared.css` — and the design has since evolved on top of that base (the Hero band, the chrome-motion hover polish); content still comes from the vault via Intake. The presentation layer is React; everything else (static output, Workers, CSP, enhancement scripts, feeds) is untouched — see ADR 0003 (decision) and ADR 0005 (the completed cutover). Fidelity is held to semantic+visual equivalence (not byte-identical) because React controls HTML serialization; during the migration `design-system/ssg/render.tsx` proved it by diffing React output against the original template for identical data (that parity harness has since been removed along with the templates). The superseded `templates/*.js` page modules have been removed after the production soak; `templates/{rows,_helpers}.js` stay (the browser Row module — the `_assets.js` registry singleton was retired once the React side threaded the asset map explicitly and nothing read it). The asset *name* contract has one owner: `lib/emit/assets.js` derives the minify+hash list from disk (`static/*.{css,js}` plus the two templates/ modules), the document shell exports `DOCUMENT_ASSET_NAMES` (every name its `url()`/importmap references) which emit asserts against the hashed map, and the Early Hints allowlist is checked against the same map — a missing or renamed asset fails the build loudly instead of shipping unhashed or 404ing under the strict CSP. There is deliberately **no `ListeningRow` design-system component**: the `/listening/` row is owned by `templates/rows.js` for the byte-equal live-update contract, so a React mirror would only drift from it unnoticed — `ArticleRow`/`ThoughtRow` already carry the shared `.row` look in the design surface (ADR 0005).

## Homepage design bake-off
`/design/`, `/design/a/`, `/design/b/`, and `/design/c/` are isolated sketches of a new homepage (`design-system/ssg/pages/DesignDirections.tsx`, styles in `static/design-directions.css`, loaded only on those routes). They do not replace `/` or `IndexPage`. Emit writes them from the same editorial projection plus the current dig and watch, and lists the four routes in the sitemap so the written-page invariant holds. Each sketch sends `noindex`.

## design-sync
The pipeline that uploads `@mattdoes/ds` to a Claude Design project so the components are editable visually. Config + notes live in `design-system/.design-sync/`; the converter builds `ds-bundle/` (the `window.MattdoesDS` bundle + preview cards) from the package's compiled `dist/`. Re-syncs run from `design-system/`. Brand fonts (JetBrains Mono) are committed under `static/fonts/` and ship into the bundle as real woff2 files — see ADR 0004 for why (and the `stripFontFace` Vite plugin it needs).
